# 両手手話動作の少数データ学習（Hand Sign VLA）

カメラで手話の手の動きを記録し、そのデータで VLA（Vision-Language-Action）モデルを追加学習させるための研究用プログラムである。少ない録画数でも新しい手話動作を覚えさせられるかを検証することを目的としている。

## 1. 研究の背景

### なぜ手話を扱うのか

手話の研究では、カメラの映像から手話を読み取るモデルと、文章から手話アバターを動かすモデルが別々に作られることが多い。しかし、聴覚障害のある人と双方向にやり取りできるロボットを作るには、相手の手話を見て（Vision）、意味を理解し（Language）、自分の手で返す（Action）までを一つのモデルで扱えるほうが望ましい。これを扱えるのが VLA モデルである。

### 解決したい問題

既存の VLA モデルを学習させるには、数万件以上の動作データと大規模な計算機が必要になる。大学の研究室や小規模な現場ではこの条件を満たすのが難しい。

そこで本研究では、**少ない手話データだけで VLA モデルに新しい動作を追加学習させられるか**を調べる。そのための工夫として、次の2点を試している。

- **幾何正規化**：手の位置や大きさのばらつきを前処理で取り除く
- **ポーズのトークン化**：手の形を番号付きの「単語」に置き換え、言語モデルが扱える形にする

## 3. 使い方

### 3.1 ダッシュボードの起動

```bash
source .venv/bin/activate
python src/ui/dashboard.py
```

起動したらブラウザで [http://localhost:8000](http://localhost:8000) を開く。

### 3.2 手話の録画

1. 「指文字収集 (50音)」または「単語収集 (両手)」タブを開く。
2. 録画したい文字・単語をクリックして選ぶ。
3. カメラの前に手を出し、**Space キー**で録画を始める。もう一度押すと止まり、CSV として保存される。
4. 1つの動作につき 5〜10 回録画する。

録画したデータは `data/raw/hiragana/` または `data/raw/words/` に保存される。

### 3.3 学習用データの作成

「モデル学習・評価」タブと「VLAデータ変換」タブで操作する。各タブの「対象データ」が、ひらがな・単語のどちらになっているかを先に確認すること。

| 順番 | ボタン              | やっていること                            | 出力先                         |
| :--- | :------------------ | :---------------------------------------- | :----------------------------- |
| 1    | 一括前処理 (正規化) | 録画 CSV をまとめ、位置と大きさをそろえる | `data/processed/dataset_*.csv` |
| 2    | SVM学習実行         | 手の形から文字を当てる分類器を学習する    | `src/learning/weights/`        |
| 3    | アクション離散化    | 手の形を K 種類の代表ポーズに分ける       | `pose_quantizer_K.joblib`      |
| 4    | JSONLエクスポート   | VLA 学習用のデータセットを書き出す        | `data/processed/vla_*.jsonl`   |

SVM の学習が終わると、カメラの前で手を止めたときに認識した文字が画面下に表示される。

### 3.4 録画データを3Dで確認する

録画が正しくできているかは、3Dビューアで確認できる。ダッシュボード右上の「3D骨格ビューア起動」を押すと、直前の録画が開く。ターミナルから開く場合は次のとおり。

```bash
python src/viewer/hand_viewer.py                                         # ファイルを選んで開く
python src/viewer/hand_viewer.py data/raw/hiragana/sign_language_a_1.csv # ファイルを指定して開く
```

| 操作           | 内容                 |
| :------------- | :------------------- |
| Space          | 再生 / 一時停止      |
| ← / →          | 1コマ戻す / 進める   |
| ↑ / ↓          | 再生速度の変更       |
| 下のスライダー | 任意のフレームへ移動 |
| O              | 別のファイルを開く   |
| T              | 人差し指の軌跡を表示 |
| マウスドラッグ | 視点の回転           |

### 3.5 コードを変更したとき

`src/ui/dashboard.py` や `src/learning/preprocess.py` などを編集したら、ターミナルで `Control + C` を押してサーバーを止め、もう一度起動する。ブラウザは `Cmd + R` で再読み込みする。

### 3.6 データを GitHub に送る

Colab で最新のデータを使うために、書き出したデータを push しておく。

```bash
git add .
git commit -m "録画データとVLAデータセットを更新"
git push origin main
```

## 4. Google Colab での学習

`openvla/openvla-7b` を 4bit 量子化して読み込み、LoRA で追加学習する。

1. 3.3 の手順で `data/processed/vla_continuous.jsonl` と `vla_discrete.jsonl` を作り、GitHub に push する。
2. Colab でリポジトリを取得するために、GitHub の個人アクセストークンを登録する。
   - Colab 左の鍵アイコン（Secrets）に、名前 `GITHUB_TOKEN` で登録する（推奨）
   - または、ノートブック先頭セルの `DIRECT_TOKEN` に直接入力する
3. `src/learning/VLA_LoRA_Notebook.ipynb` を Colab で開き、1〜4番目のセルを順に実行する（ライブラリの導入とモデルの読み込み）。
4. 5番目のセルの `Experiment_Type` で、比較したい実験を選ぶ。

   | 設定値                 | 比較する内容                                                   |
   | :--------------------- | :------------------------------------------------------------- |
   | `compare_data_format`  | 連続値の軌跡として予測する場合と、ポーズ番号として予測する場合 |
   | `compare_lora_rank`    | LoRA のランク 8 と 32                                          |
   | `compare_prompt_style` | 指示文を記号（ID）にした場合と、日本語の文にした場合           |

5. 6番目のセルを実行すると、2条件の学習曲線を重ねたグラフ（`vla_comparison_*.png`）が保存される。

詳しい手順は [docs/colab_setup_guide.md](docs/colab_setup_guide.md) にまとめてある。

## 6. 使っている技術

### 6.1 MediaPipe Hands による手の検出

カメラ映像から、左右の手それぞれ 21 か所の関節の3次元座標 (x, y, z) を取り出す。両手で合計 126 個の数値になる。画像をそのまま扱うよりデータ量が大幅に小さくなるため、少ない計算資源で学習できる。

### 6.2 幾何正規化（preprocess.py）

カメラとの距離や手が映る位置が変わっても同じ形として扱えるように、次の変換をかける。

1. **手首を原点にする**：手首（ID 0）の座標を (0, 0, 0) とし、他の関節を手首からの相対位置に直す。
2. **大きさをそろえる**：手首から中指の付け根（ID 9）までの距離が 1 になるように全体を縮める。手の大きさの個人差もこれで小さくなる。

学習時には、さらに ±15 度の回転と少しの拡大縮小を加えたデータも作り、データ数を増やしている。

### 6.3 SVM による文字の分類

正規化した座標に、指先どうしの距離や関節の曲がり角度を加えたものを入力にして、RBF カーネルの SVM で文字を分類する。SVM は少ないデータでも安定して境界を引けるため、1文字あたり数回の録画でも十分な精度が出やすい。

### 6.4 ポーズのトークン化（quantizer.py）

言語モデルは連続した小数をそのまま出力するのが苦手である。そこで K-Means で手の形を K 種類（標準は 64）の代表ポーズに分け、各フレームを `<pose_12>` のような番号で表す。これにより、手話の動きを「ポーズ番号の並び」として言語モデルに学習させられる。

## 7. 予備実験の結果

「あ・い・う・え・お」を各3回、計15件録画したデータで LoRA 学習の流れを試した。

```text
Epoch 01/10 - Loss: 2.5840 - Accuracy: 50.20%
Epoch 02/10 - Loss: 2.1576 - Accuracy: 63.00%
Epoch 03/10 - Loss: 2.0923 - Accuracy: 63.00%
...
Epoch 10/10 - Loss: 2.1035 - Accuracy: 63.00%
```

- 2エポック目で損失が 2.58 から 2.15 に下がり、正解率は 50.2% から 63.0% に上がった。正規化とトークン化によって、少ないデータでも早い段階で学習が進んでいると考えられる。
- 3エポック目以降は 63.0% で変化しなくなった。1文字3件ではデータの種類が足りず、これ以上の一般化ができていない可能性が高い。
- 精度を上げるには、1文字あたりの録画を 5〜10 件に増やす必要があると考えている。

## 8. 今後の課題

### 8.1 追加で行いたい実験

1. **クラスタ数 K の比較**：K を 16, 32, 64, 128, 256 と変え、再構成誤差（MSE）の変化を調べて適切な K を決める。
2. **他人の手への適用**：手の大きさが違う人に録画してもらい、正規化によって認識精度が保たれるかを確かめる。
3. **ノイズへの強さ**：座標にノイズを加えたりフレームを間引いたりして、トークン化と復元がどこまで耐えられるかを調べる。

### 8.2 会話の速さへの対応

現在の文字入力は、手が止まったことを検出してから SVM で判定している。実際の会話では手は止まらずに動き続けるため、このままでは遅い。LSTM や Transformer、CTC 損失などを使い、動きを止めずに連続して読み取れるようにする必要がある。

### 8.3 両手を使う単語

データは最初から右手と左手を合わせた 126 次元で記録しているため、両手を使う単語（「りんご」など）もプログラムを変えずに扱える。ただし、1フレームずつ判定する SVM では動きを含む単語の判定は難しい。VLA モデルは指示文から両手の動きの並びを直接出力する形なので、両手の単語データを集めれば学習させられる見込みがある。
